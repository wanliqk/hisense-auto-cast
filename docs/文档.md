~~~markdown
# 任务：开发海信电视自动投屏客户端 Hisense Auto Cast

## 一、任务目标

开发一个 Windows 桌面端 Electron 应用，用于自动连接海信电视的“电脑投屏”服务，并自动将 Windows 主屏幕投送到电视。

目标流程：

启动程序
→ 自动获取主屏幕
→ 自动连接海信电视
→ 完成 WebSocket 协议协商
→ 自动开始屏幕采集
→ MediaRecorder 编码
→ WebSocket 持续推送媒体数据
→ 网络断开后自动重连

第一版不需要复杂 UI，以“能够稳定自动投屏”为第一目标。
~~~

# 四、处理 ConnectACK

电视会返回：

```json
{
  "format": {
    "codec": "h264,pcm",
    "video": "webm"
  },
  "frameRate": 60,
  "protocolVersion": 1,
  "resolution": 1080,
  "result": "OK",
  "security": 0,
  "cmd": "ConnectACK"
}
```

只有：

```text
result === "OK"
```

时才允许继续。

保存电视选择的：

```text
security
protocolVersion
resolution
frameRate
format
```

然后使用这些参数启动屏幕采集。

如果返回错误，记录完整日志并进入重连流程。

# 五、自动屏幕捕获

原网页使用：

```javascript
navigator.mediaDevices.getDisplayMedia()
```

但是 Electron 客户端的目标是不弹出“选择共享内容”窗口。

使用 Electron 当前稳定版本推荐的屏幕捕获方式，实现：

```text
默认自动选择 Windows 主显示器
```

优先考虑：

```javascript
desktopCapturer
```

以及：

```javascript
session.setDisplayMediaRequestHandler(...)
```

具体 API 根据当前 Electron 版本实现。

不要依赖已废弃 API，除非当前稳定版确实要求。

要求：

1. 默认获取主屏幕。
2. 不要求用户每次手工选择屏幕。
3. 支持未来扩展配置指定显示器。
4. 主显示器变化后能够重新获取 source。

# 九、媒体数据发送

这是本项目最重要的协议要求：

不要自行添加：

```text
Header
Length
CRC
消息序号
自定义媒体协议
```

海信原程序直接：

```javascript
mediaRecorder.ondataavailable = event => {
  if (event.data && event.data.size > 0) {
    socket.send(event.data)
  }
}
```

因此必须直接将 MediaRecorder Blob 作为 WebSocket Binary Message 发送。

流程：

```text
MediaRecorder
      ↓
Blob
      ↓
WebSocket.send(blob)
      ↓
海信电视
```

# 十、Feedback

格式：

```json

  "cmd": "Feedback"
}
```

```text
3 秒
```

发送一次。

# 十一、发送缓冲区背压控制

每：

```text
200 ms
```

检查一次：

```javascript
socket.bufferedAmount
```

和：

```javascript
mediaRecorder.state
```

参考原 WebMirror 逻辑。

计算：

```javascript
upperLimit = videoBitsPerSecond / 4
lowerLimit = 1024
```

如果：

```javascript
bufferedAmount > upperLimit
```

并且：

```text
mediaRecorder.state === recording
```

执行：

```javascript
mediaRecorder.pause()
```

并发送：

```text
Feedback(paused)
```

当：

```javascript
bufferedAmount < 1024
```

且 Recorder 为：

```text
paused
```

执行：

```javascript
mediaRecorder.resume()
```

并发送：

```text
Feedback(recording)
```

# 十二、处理 Finish

电视可能主动发送：

```json
{
  "cmd": "Finish"
}
```

收到后：

```text
停止 MediaRecorder
停止 MediaStream
关闭 WebSocket
清理定时器
进入断线状态
```

然后根据自动重连策略决定是否重新连接。

# 十三、Watchdog

按照海信原实现：

如果连续：

```text
45 秒
```

没有收到新的：

```text
MediaRecorder ondataavailable
```

数据，则认为投屏异常。

执行：

```text
stopMirror()
```

随后自动重新建立连接。

每收到正常媒体数据时重置 Watchdog。

------

# 十四、断线自动重连

这是本客户端相对海信网页必须增加的功能。

以下情况都需要进入自动恢复流程：

```text
WebSocket close
WebSocket error
网络断开
电视重启
Connect 失败
MediaRecorder 异常
45 秒 Watchdog 超时
```

推荐重连策略：

```text
第一次：1 秒
第二次：2 秒
第三次：5 秒
之后：每 10 秒
```

成功连接后重置重连计数。

必须避免：

```text
同时启动多个 WebSocket
同时启动多个 MediaRecorder
重复捕获屏幕
重复定时器
```

设计明确的生命周期状态。

例如：

```text
DISCONNECTED
CONNECTING
NEGOTIATING
CAPTURING
STREAMING
RECONNECTING
STOPPING
```

# 二十一、验收标准

必须满足：

### 基础

- Electron 正常启动。
- 能连接 `192.168.110.215:8765`。
- Connect / ConnectACK 正常。
- 正确读取电视协商参数。

### 投屏

- 自动捕获主显示器。
- 不需要每次人工选择共享屏幕。
- MediaRecorder 正常工作。
- Binary Blob 能持续发送。
- 海信电视可以稳定显示 PC 屏幕。

### 稳定性

拔掉网络后恢复：

```text
能够自动重新连接
```

电视重启后：

```text
能够自动恢复连接
```

WSS 异常：

```text
不会产生多个重复连接
```

MediaRecorder 异常：

```text
能够清理旧资源
```

### 运行

连续投屏至少：

```text
30 分钟
```

观察：

```text
内存不能持续明显增长
WebSocket bufferedAmount 不能无限增长
不能出现多个 MediaRecorder
不能出现多个重复定时器
```
